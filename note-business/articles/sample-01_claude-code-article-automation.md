# 【試作記事サンプル】Claude Codeでブログ記事を“ほぼ自動”で書く方法｜初心者がつまずく工程を全部つぶした手順

> これは `pipeline/` のプロンプトで生成することを想定した**試作サンプル**です。
> 実際に使うときは、Claude Code で生成し直し、★あなたの実体験・実数を足してから投稿してください。
> 数値や仕様で【要確認】が付く箇所は、投稿前に必ず確認を。

---

**この記事の対象読者**：AIに記事を書かせてみたが「薄い」「結局自分で直す方が早い」となった人
**読むと分かること**：丸投げではなく“工程を分けて任せる”ことで、人の作業を最小化する具体手順
**かかる時間**：1記事あたり、人の作業はおよそ10〜15分まで圧縮できます

---

## なぜ「AIに記事を丸投げ」すると失敗するのか

「〇〇について書いて」と一言頼んで出てきた文章を、そのまま使えなかった経験はありませんか。

理由はシンプルで、**AIに"設計"を渡していないから**です。
記事の質を決めるのは、文章力ではなく「誰の・どんな悩みを・どう解決するか」という設計。
ここが曖昧なまま生成すると、当たり障りのない薄い文章になります。

そして重要な事実があります。note社が約30万件の有料記事を分析したデータによると、
**記事の文字数と売上にはほぼ相関がありません**【要確認：出典 note社2026年1月公開データ】。
つまり「AIで長文を量産する」戦略は、そもそも筋が悪いのです。

やるべきは長文化ではなく、**工程を分けて、それぞれをAIに正しく任せること**。
順番に見ていきます。

## 工程を5つに分解する

記事作成を1つの作業と考えるから、丸投げになって失敗します。
次の5工程に分けると、それぞれでAIの精度が一気に上がります。

1. **キーワード調査**：何の悩みを解決する記事にするか決める
2. **構成設計**：タイトルと見出しを決める（←ここだけ人が選ぶ）
3. **執筆**：構成に沿って本文を書かせる
4. **レビュー**：AIに自己採点させ、人が事実確認する
5. **整形**：投稿用に見出し・要約・価格を整える

ポイントは、**②の「どのタイトルでいくか」だけ人が決める**こと。
ここさえ握れば、残りはほぼAIに任せられます。

## 工程①：悩みキーワードを出させる

最初にやるのは「何について書くか」をAIに広げてもらうことです。
ここで大事なのは、いきなり「テーマを決めて」と聞かないこと。
**読者と悩みを指定して、候補を10個出させる**のがコツです。

（無料パートではここまで。実際に使うプロンプト全文と、②〜⑤の具体的なやり方、
そして人が確認すべき1工程の中身を、この先で全部公開します）

---有料ライン---
※ note投稿時はこの位置から下を有料エリアに設定。推奨価格：980円

## 工程①の実物プロンプト（コピペ可）

```
あなたはnoteで稼ぐためのコンテンツ戦略家です。
【ジャンル】AI活用ノウハウ
【読者】AIに興味はあるが何から始めればいいか分からない会社員
このジャンルで需要がありそうな「具体的な悩みキーワード」を
WebSearchも使って10個、想定単価つきで提案してください。
最後に最初に書くべき1本を理由つきで選んでください。
```

このプロンプトを投げると、検索需要のあるテーマが単価つきで並びます。
この中から「自分が少しでも書けて、単価980円以上を狙えるもの」を選びます。

## 工程②：タイトルと構成（←人が選ぶ唯一の工程）

構成は、次のプロンプトで5タイトル＋見出し案を出させます。

```
【テーマ】（①で選んだもの）
【読者】（誰のどんな悩みか）
タイトル案を5つ（具体的な悩み or 数字 or 手順を入れる）と、
H2見出し4〜6個の構成、有料/無料の境界提案を作って。文字数は追わないで。
```

ここで**あなたがタイトルを1つ選びます**。
この選択が記事の成否の8割を決めるので、ここだけは人の仕事として残します。

## 人が必ずやる「最後の1工程」

全部AIに任せても、**ここだけは絶対に人がやってください**。

- AIが【要確認】とした事実（数値・仕様・価格）を自分で確認する
- 通し読みして違和感・嘘っぽさを消す
- 自分の体験・実数を1つ足す ← これが信頼になり、売上を分ける

この10分を惜しむと、誤情報や“AIっぽい薄さ”が残り、結局売れません。
逆にここさえやれば、AIで作った記事でも十分に価値ある商品になります。

## まとめ

- 丸投げではなく「5工程に分けて任せる」
- 人が握るのは「タイトル選び」と「最終チェック」の2つだけ
- 長さではなく課題解決の濃さで勝負する

この手順をテンプレート化すれば、1記事の人の作業は10〜15分。
あとはこれを淡々と回すだけです。
